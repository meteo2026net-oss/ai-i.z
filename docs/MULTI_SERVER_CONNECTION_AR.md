# دليل الاتصال متعدد الخوادم — AI I.Z

فرع العمل: `feature/multi-server-connection-setup` (من المرجع المجمد `98ad341`).

## الأنماط

1. **مركزي:** يستخدم `AI_IZ_API_BASE_URL` المضبوط وقت بناء التطبيق.
2. **خاص:** يدخل المستخدم عنوان HTTPS لخادمه. يُختبر عبر `GET /api/meta` وليس الاعتماد على `/api/health` وحده.

## الاكتشاف

`GET /api/meta` يعيد: `protocol`, `apiVersion`, `capabilities`, و`oauth.googleClientId` / audience / issuer **دون أسرار**.

التطبيق يرفض الربط إذا:
- البروتوكول ≠ `ai-iz-identity/v1`
- قدرات إلزامية ناقصة
- Client ID فارغ
- العنوان غير HTTPS (ما عدا محاكي Debug)

## الجلسات

عند تغيير بصمة الخادم (عنوان + Client ID) تُمسح رموز الجلسة من SecretVault. لا تنتقل الجلسات بين الخوادم.

## OAuth

Client ID المعروض في meta يجب أن يطابق إعداد Google على الخادم. المستخدم يعيد تسجيل الدخول بعد تغيير الخادم.

## Runner

تنفيذ SQL والأوامر يبقى **501**.

## تجربة الميزة

1. من التطبيق افتح المسار `server_connection` (إعداد الاتصال).
2. اختر مركزي أو خاص، أدخل URL، **اختبار الاتصال**، ثم **حفظ وربط**.
3. سجّل الدخول عبر Google على ذلك الخادم.

بدون خادم منشور: يمكن فتح الشاشة واختبار فشل الشبكة/عنوان غير صالح. نجاح الاكتشاف وتسجيل الدخول يحتاج API يعمل مع `/api/meta`.
