## ما ثبت تنفيذه في النسخة المفحوصة

- تطبيق Android أصلي باستخدام Kotlin وJetpack Compose.
- تسجيل الدخول عبر Android Credential Manager للحصول على Google ID token، ثم التحقق منه مباشرة في AI I.Z API؛ Firebase Authentication ليس جزءاً من مسار تسجيل الدخول.
- إنشاء/استعادة حساب AI I.Z بالاعتماد على Google OIDC subject الثابت، مع access tokens خاصة بالتطبيق وrefresh-token rotation وكشف إعادة الاستخدام.
- تخزين رموز الجلسة محلياً باستخدام Android Keystore.
- مخطط PostgreSQL لخدمات الهوية والجلسات وسجلات التدقيق وبيانات المستخدم وموافقات Runner.
- واجهات API للبيانات الشخصية مع اشتقاق الملكية من جلسة الخادم، والتحقق من المدخلات، وسجلات تدقيق، وسجلات تشغيل append-only.
- موافقات خادمية مرتبطة بالمستخدم والإجراء والهدف الدقيق وSHA-256 للحمولة، مع انتهاء صلاحية واستهلاك ذري لمرة واحدة.
- ربط شاشة الموافقات في Android بواجهات الموافقات الخادمية؛ لا ينفذ Android عمليات GitHub أو SQL الحساسة بعد الموافقة.
- خدمة Runner منفصلة تتحقق من جلسة AI I.Z عبر خدمة الهوية، وتوفر فحص الصحة وقراءة بيانات مخطط PostgreSQL للمستخدمين المدرجين صراحة في قائمة السماح.
- Firebase Authentication وFirestore persistence وApp Check أزيلت من مسار الهوية/بيانات المستخدم في هذا الفرع. ما زال Firebase AI مستخدماً لتكامل Gemini، لذلك لا يصح وصف المشروع بأنه أزيل منه Firebase بالكامل.
- شاشات Android ومكونات التنقل والمحادثة والمهام والمستودعات ومركز Universal Studio موجودة، لكن وجود الشاشة لا يثبت اكتمال تدفقها end-to-end.

## ما لا يزال غير منفذ أو غير مثبت

| المجال | الحالة / شرط الإغلاق |
|---|---|
| تنفيذ Runner عن بعد | مسارات تشغيل الاختبارات وSQL والتنفيذ الموافق عليه ترجع HTTP 501 عمداً؛ يلزم عامل معزول موثوق قبل تفعيلها |
| تنفيذ SQL | غير متاح؛ يلزم محلل SQL موثوق، دور PostgreSQL للقراءة فقط للاستعلامات، حدود زمن/صفوف، ومنع DDL والوظائف غير الآمنة |
| تنفيذ أوامر GitHub الحساسة | الموافقات الخادمية موجودة، لكن Runner لا ينفذ العمليات بعد؛ يلزم تكامل خادمي بأسرار GitHub App محمية |
| نشر API وPostgreSQL وRunner | لم يثبت نشر أي خدمة إنتاجية أو إعداد TLS/المراقبة/النسخ الاحتياطي |
| إعداد Google OAuth | لم يثبت إعداد Web Client ID/Audience إنتاجي أو نجاح تسجيل الدخول على خادم منشور |
| اختبار جهاز فعلي | لم يثبت اختبار APK على جهاز Android فعلي، بما يشمل RTL/LTR وإمكانية الوصول |
| ترحيل البيانات التاريخية | لا يوجد استيراد تلقائي لبيانات Firestore القديمة؛ يتطلب ذلك قرار احتفاظ وخطة تصدير/استيراد محكومة |
| إعداد مزودي AI | يلزم اختبار مفاتيح المستخدم والحصص والأخطاء والتحويل الاحتياطي في بيئة تشغيل حقيقية |
| دورة إنشاء المشروع | يلزم اختبار قبول متكامل من وصف الفكرة إلى المتطلبات والتصميم والملفات والبناء والتسليم |
| الإنجليزية وLTR | الترجمة الكاملة والتبديل الديناميكي لم يثبت اكتمالهما |
| Gradle Wrapper | ملفات Wrapper scripts/JAR غير موجودة؛ CI يبني باستخدام Gradle المُدار، والبناء المحلي يتطلب Gradle مثبتاً |
| Release والتوزيع | لا يوجد APK Release موقع بمفتاح إصدار خارجي ولا مسار تحديث/تراجع مثبت |
| الخصوصية واستمرارية العمل | يلزم استكمال حذف الحساب والبيانات، وسياسة الخصوصية، والنسخ الاحتياطي واختبار الاستعادة |

## بوابات الأمان الحالية

1. لا تفعّل تنفيذ SQL أو shell أو كود مولّد على خادم الإنتاج.
2. لا تعتبر قرار الموافقة أو تقرير Android دليلاً على تنفيذ العملية؛ يلزم تنفيذ خادمي موثق بعد استهلاك الموافقة الدقيقة.
3. لا تمنح Runner صلاحيات superuser أو بيانات اعتماد ترحيل قاعدة البيانات.
4. لا تضع مفاتيح OAuth أو GitHub أو توقيع Android في المستودع أو المحادثة.
5. لا تدمج PR #6 ولا تنشر إصداراً نهائياً قبل اختبارات القبول والإعدادات التشغيلية المطلوبة.

## الخطوات التالية ذات الأولوية

1. إكمال تدفقات Android الأساسية واختبارها على مستوى ViewModel/Repository وواجهات المستخدم.
2. تحديد بيئة نشر مجانية/مناسبة وتوفير إعدادات OAuth وPostgreSQL في مخزن أسرار آمن.
3. تصميم وتنفيذ عامل Runner معزول؛ البدء بعمليات allowlist محدودة، ثم إضافة SQL آمن فقط بعد مراجعة السياسة.
4. إضافة ترحيل اختياري مضبوط للبيانات القديمة إذا قرر مالك المنتج الاحتفاظ بها.
5. إكمال الإنجليزية/LTR، واختبارات الوصول والأجهزة، وتدفق حذف الحساب.
6. إعداد توقيع Release خارجي واختبار تثبيت/تحديث/تراجع قبل النشر.
