# خارطة دورة حياة المشاريع في AI I.Z
## المرجع المرحلي المعتمد لتحويل الفكرة إلى تطبيق جوال أو برنامج متكامل

هذه الخارطة هي التسلسل الأساسي الذي يديره مركز قيادة المشروع في AI I.Z. يكيّف النظام المراحل بحسب نوع المشروع وحجمه، ويوثق سبب تخطي أي مرحلة غير لازمة. لا يعني إكمال وثيقة أو واجهة فارغة أن الوظيفة قد نُفذت.

## المجموعة 1 — الفكرة والمتطلبات
1. **استقبال الفكرة والمراجع:** وصف المستخدم، الصور، الملفات، الروابط، والمصادر.
2. **تحليل المجال والمستخدمين:** المجال، الفئات المستهدفة، الأهداف، ورحلات الاستخدام.
3. **المتطلبات الوظيفية:** الوظائف، العمليات، المدخلات، المخرجات، ومعايير القبول.
4. **المتطلبات غير الوظيفية:** الأداء، الأمان، الخصوصية، الاعتمادية، سهولة الاستخدام، والتوسع.
5. **الأسئلة واكتشاف النواقص:** أسئلة تدريجية، شرح المصطلحات، وتمييز الحقائق عن افتراضات AI.
6. **وثيقة المتطلبات:** نطاق واضح، قيود، افتراضات، أولويات، واعتماد المستخدم.

## المجموعة 2 — تصميم UI/UX قبل البرمجة
7. **خريطة الصفحات والتنقل:** كل الشاشات والأقسام والقوائم والنوافذ وتدفقات التنقل.
8. **الأجهزة والمنصات:** Android وiOS واللوحي وغيرها حسب النطاق المعتمد.
9. **Wireframes:** تخطيط أولي لكل شاشة وحالة.
10. **القياسات والتجاوب:** الهوامش والمسافات والأبعاد والخطوط وأهداف اللمس ومناطق النظام ووحدات القياس المناسبة.
11. **Design System:** الألوان والخطوط والأيقونات والمكونات المشتركة وحالاتها.
12. **التصميم النهائي:** كل الشاشات والحالات، الفاتح والداكن، RTL وLTR.
13. **النموذج التفاعلي:** ربط الشاشات ومحاكاة التفاعلات والرحلات.
14. **مراجعة واعتماد UI/UX:** سهولة الاستخدام، الاتساق، إمكانية الوصول، ومطابقة المتطلبات.

## المجموعة 3 — التقنيات والهندسة
15. **اختيار لغة البرمجة وإطار العمل:** توصية مبررة وبدائل وتكلفة، مع اعتماد المستخدم.
16. **اختيار قاعدة البيانات:** محلية أو سحابية أو هجينة، مقارنة الأداء والتكلفة والتوسع.
17. **تصميم ERD وقاموس البيانات:** الجداول والحقول والأنواع والمفاتيح والعلاقات والقيود؛ لا تنفيذ فعلي قبل الاعتماد.
18. **معمارية التطبيق:** الطبقات والوحدات وتدفق البيانات والاتصال والتخزين والمزامنة.
19. **الهوية والمصادقة:** التسجيل والدخول والجلسات واستعادة الحساب والتحقق.
20. **الأدوار والصلاحيات والتغييرات:** مصفوفة الصلاحيات والموافقات وسجل التدقيق وصلاحيات الوكلاء.
21. **الخدمات والتكاملات:** مزودو AI وGitHub والتخزين والإشعارات وواجهات API والبدائل والتكلفة.

## المجموعة 4 — الحماية والجودة والتشغيل
22. **الأمن ونموذج التهديد:** الأسرار والاتصالات والبيانات والصلاحيات وعزل التنفيذ وفحص الاعتماديات.
23. **استراتيجية الاختبار:** اختبارات الوحدة والتكامل والواجهة والأداء والأمان وإمكانية الوصول والأجهزة.
24. **النشر والتشغيل والإصدارات:** البيئات والبناء والتوقيع والتوزيع والتحديث والتراجع والمراقبة.
25. **النسخ الاحتياطي والتعافي:** الاحتفاظ والاستعادة وأهداف RPO/RTO واختبارات التعافي.
26. **الموارد والتكلفة:** الاستضافة والتخزين والذكاء الاصطناعي والتراخيص والبدائل وموافقة الإنفاق.
27. **خطة التنفيذ:** وحدات ومهام وأولويات واعتماديات ومسؤوليات ومعايير قبول.

## المجموعة 5 — المراجعة والاعتماد
28. **مراجعة الاتساق:** مطابقة المتطلبات والتصميم والبيانات والمعمارية والأمن والتكاملات.
29. **حزمة المواصفات التنفيذية:** تجميع الوثائق والمخططات والعقود والاختبارات والخطة في نسخة مترابطة.
30. **بوابة الاعتماد:** إظهار القرارات المعلقة، إصدار نسخة معتمدة، وعدم بدء البرمجة قبل موافقة المستخدم.

## المجموعة 6 — البناء والتنفيذ
31. **بيئة التطوير:** التبعيات وGit والفروع والبيئات وإعدادات التشغيل.
32. **قاعدة البيانات والخلفية:** المخطط والترحيلات والسياسات وواجهات API والمصادقة والتخزين.
33. **واجهات الجوال:** تطبيق الشاشات المعتمدة مع الالتزام بمرجع التصميم والقياسات.
34. **الوظائف والوكلاء:** منطق الأعمال والتكاملات والوكلاء بصلاحيات محدودة وموافقات مناسبة.
35. **الدمج والتحقق المرحلي:** دمج الأجزاء والاختبارات وإصلاح الأخطاء ومراجعة الشفرة.

## المجموعة 7 — الإطلاق والتحسين المستمر
- اختبار قبول المستخدم ومطابقة التصميم.
- تدقيق الأمان والأداء وإمكانية الوصول.
- تجهيز الإصدار وسجل التغييرات.
- النشر والتوزيع بعد الموافقة.
- مراقبة الأعطال والأداء والتكاليف.
- الصيانة وتحديث الاعتماديات وإصلاح الأخطاء.
- إدارة التغييرات وتحليل أثرها.
- النسخ الاحتياطي واختبار الاستعادة.
- التحسين وإصدار تحديثات دورية.

## قدرات مستمرة عبر المراحل
- مركز قيادة يعرض المرحلة والخطوة التالية والقرارات المطلوبة.
- مدير سير عمل يضيف المراحل ويقسمها ويعيد فتحها ويوثق أسباب التخطي.
- وكلاء متخصصون يعملون ضمن صلاحيات محددة.
- سجل قرارات وتغييرات وإصدارات.
- إدارة ملفات ومراجع مرتبطة بالمتطلبات.
- تحليل أثر كل تعديل على الشاشات والبيانات والشفرة والاختبارات.
- تقدم فعلي قائم على أدلة التنفيذ والتحقق، لا على إنشاء الملفات فقط.

## بوابات الانتقال
- لا يبدأ تصميم UI النهائي قبل اكتمال المتطلبات وخريطة الصفحات.
- لا تبدأ البرمجة قبل اعتماد UI/UX والتقنيات والبيانات والمعمارية والأمن وخطة الاختبار.
- لا يتم النشر أو الحذف أو الإنفاق المدفوع أو تغيير جوهري دون الموافقة المطلوبة.
- لا تعتبر أي مرحلة مكتملة دون مخرجات ومعايير قبول وأدلة تحقق.
