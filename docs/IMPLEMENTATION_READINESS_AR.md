# AI I.Z — سجل الجاهزية والتنفيذ

آخر مراجعة للمستودع: 2026-11-15

هذا الملف يميّز بين وجود الشفرة، ونجاح الاختبار، وجاهزية الخدمة الفعلية. لا تُعد الوظيفة مكتملة لمجرد وجود شاشة أو واجهة API لها.

## ما هو موجود في المستودع

- تطبيق Android أصلي باستخدام Kotlin وJetpack Compose.
- تسجيل دخول Firebase ومكونات Firestore وApp Check.
- طبقة تنسيق مزودي الذكاء الاصطناعي وآلية التحويل الاحتياطي.
- واجهات تكامل GitHub للفروع والملفات والالتزامات وطلبات الدمج وActions.
- مولّد مشاريع عام ومكونات لمساحة العمل ومحادثة الوكيل.
- قاعدة Room محلية وWorkManager لتنظيم المهام.
- عميل Retrofit لعقد Backend Runner.
- شاشات للمشاريع والمهام والتكاملات وقواعد البيانات والاختبارات والأمان.
- اختبارات وحدة لبعض سياسات الأمان والمستودعات والنماذج.

## تغييرات توثيقية وتشغيلية حديثة

- إضافة وتحسين لوحة التحكم الرئيسية بملخص المشاريع والمهام والموافقات.
- إضافة سير GitHub Actions لبناء Android وتشغيل الاختبارات ورفع APK تجريبي.
- توحيد متطلبات JDK في دليل المشروع مع بيئة CI (JDK 21).
- تصحيح دليل الإعداد لإزالة تعليمات PAT الخاصة بمستودعات قديمة.
- توثيق عقد Backend Runner ومتطلبات المصادقة والموافقات والعزل الأمني دون الادعاء بوجود خادم منشور.

## فجوات تمنع إعلان الجاهزية النهائية

| المجال | الحالة التي يجب إثباتها |
|---|---|
| Android build | نجاح CI وإنشاء APK قابل للتثبيت |
| واجهة المستخدم | مراجعة الشاشات على جهاز فعلي، RTL/LTR، الوضع الفاتح والداكن، وإمكانية الوصول |
| Firebase | إعداد مشروع إنتاجي واختبار Auth وFirestore Rules وApp Check |
| GitHub | اختبار تدفقات القراءة والكتابة مع Token محدود الصلاحيات |
| AI providers | اختبار مفاتيح المستخدم، الحصص، الأخطاء، والتحويل الاحتياطي |
| Backend Runner | الخادم غير موجود ضمن هذا المستودع حتى تاريخ المراجعة؛ يلزم تنفيذه ونشره واختباره |
| قاعدة البيانات | لا تُفعّل عمليات SQL البعيدة قبل وجود خادم آمن وعزل وصلاحيات وموافقات خادمية |
| دورة إنشاء المشروع | اختبار متكامل من وصف الفكرة حتى الملفات والبناء والتسليم |
| الإصدار | توقيع Release بمفتاح خارجي واختبار التثبيت والتحديث |
| الخصوصية | استكمال سياسة الخصوصية وتدفق حذف الحساب والبيانات وفق الخدمات المفعلة |

## قواعد إعلان الإنجاز

1. لا تُعلن نسبة اكتمال رقمية دون تعريف طريقة حسابها ومخرجاتها.
2. افصل بين «الشفرة موجودة»، و«اختبار آلي ناجح»، و«اختبار على جهاز»، و«خدمة إنتاجية منشورة».
3. لا تضع بيانات اعتماد أو مفاتيح أو ملفات توقيع في Git.
4. لا تعتبر وجود عميل API دليلاً على وجود الخادم.
5. لا تعتبر APK تجريبياً إصداراً إنتاجياً.
6. سجّل رابط CI والنتيجة الفعلية لكل دفعة تطوير.

## الخطوة التالية

إكمال تحقق CI الحالي، ثم معالجة أخطاء البناء والاختبارات إن ظهرت، ومواصلة اختبار واجهات المستخدم والتدفقات الأساسية. بعد ذلك يلزم تنفيذ Backend Runner وإعداد Firebase الإنتاجي قبل أي ادعاء بأن جميع وظائف AI I.Z تعمل end-to-end.
